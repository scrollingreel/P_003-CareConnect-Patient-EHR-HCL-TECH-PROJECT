# MAMARetrieval Benchmark Evaluation

**Evaluation of the ApexCare Hospital RAG pipeline against the MAMARetrieval clinical guideline retrieval benchmark.**

---

## What is MAMARetrieval?

MAMARetrieval is an external retrieval benchmark for medical RAG systems, built from midwifery and obstetric clinical guidelines (WHO, Tanzania MOH, Zanzibar MOH). It is NOT the project's original dataset.

- **Repository:** https://github.com/nmrenyi/mamaretrieval
- **HuggingFace:** https://huggingface.co/datasets/nmrenyi/mamaretrieval
- **License:** Research use only — see [LICENSE](https://raw.githubusercontent.com/nmrenyi/mamaretrieval/main/releases/mamaretrieval-hf-v0.1.0/LICENSE)
- **Citation:** Ren, Yi. *MamaRetrieval* v0.1.0. 2026.
- **Domain:** Midwifery / OBGYN / neonatal care (Zanzibar clinical context)
- **Queries:** 3,185 (all `per_chunk` type, LLM-generated by Qwen3.6-27B-FP8)
- **Corpus:** ~63,650 chunks from 19 clinical guideline sources (~17,827 chunks exported in v0.1.0)
- **Labels:** 36,418 (query, chunk) pairs (v0.1.0 Tier 2 — top-3 union of 6 retrievers)
- **Relevance score:** `D1 x (D2 + D3 + D4) in {0..6}`

### Dataset Configs (v0.1.0)

| Config | Rows | Key Columns |
|---|---:|---|
| `queries` | 3,185 | `query_id`, `query_text`, `seed_chunk_id` |
| `rankings` | 57,330 | `query_id`, `retriever`, `rank`, `chunk_id`, `score` |
| `judgments` | 36,418 | `query_id`, `chunk_id`, `d1_topic`, `d2_meaningful`, `d3_actionable`, `d4_density`, `score` |
| `chunks` | 17,827 | `chunk_id`, `text` |

## Data Access

**The dataset requires HuggingFace authentication.** It is a private/gated repository.

### Setup Steps

```bash
# 1. Create account at https://huggingface.co
# 2. Accept the dataset terms at:
#    https://huggingface.co/datasets/nmrenyi/mamaretrieval
# 3. Login:
python -m huggingface_hub.cli login
# OR
huggingface-cli login
# 4. Run the download script:
python evaluation/mamaretrieval/scripts/01_download_benchmark.py
```

## Directory Structure

```
evaluation/mamaretrieval/
    raw/               # Raw files from HuggingFace (gitignored)
    processed/         # Schema reports, download summaries
    corpus/            # corpus.jsonl (chunks.parquet converted)
    queries/           # queries.jsonl
    qrels/             # qrels.jsonl (judgments.parquet converted)
    results/           # query_results.csv, metrics.json, error_analysis.csv, ablation_results.csv
    reports/           # evaluation_report.md, ieee_results_table.csv, ieee_results_table.tex
    scripts/
        01_download_benchmark.py   # Download + verify from HuggingFace
        02_build_index.py          # Build isolated TF-hash vector index
        03_run_evaluation.py       # Run queries, compute metrics
        04_generate_tables.py      # Generate IEEE CSV + LaTeX tables
        05_ablation.py             # Optional ablation (K, threshold sweeps)
```

## Retrieval Configuration

The evaluation uses the **exact same configuration** as the production system:

| Parameter | Value | Source |
|---|---|---|
| Embedding | TF-hash bag-of-words (768-dim, L2-normalized) | `VectorStoreConfig.java` |
| Vector Store | SimpleVectorStore (cosine similarity, in-memory) | `VectorStoreConfig.java` |
| Top-K | 4 | `application.yml:app.rag.top-k` |
| Similarity Threshold | 0.10 | `application.yml:app.rag.similarity-threshold` |
| Chunk Size | 1,400 chars | `KnowledgeDocumentService.java` |
| Chunk Overlap | 200 chars | `KnowledgeDocumentService.java` |

**The embedding algorithm is a re-implementation of `VectorStoreConfig.java` in Python.**
It is NOT a semantic embedding model. This is the actual production implementation.

---

## Important Constraints

- The hospital production knowledge base (H2 database + production SimpleVectorStore) is **NOT touched** by the evaluation.
- The clinical safety blocklist (11 terms) is **NOT bypassed** during evaluation.
- Relevance labels (qrels) are **NEVER used during retrieval** — only post-retrieval for metric calculation.
- Generation evaluation requires a valid Gemini API key; without it, only the deterministic text fallback is available.
- All raw benchmark data is **gitignored** per the benchmark license (no redistribution of chunk text).
